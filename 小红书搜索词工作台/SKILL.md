# 小红书搜索词工作台

## 它是什么 / 不是什么（先搞清定位）

**它是「弹药库 + 判定依据」，不是一个自动出选题的机器。**

两个用法：

| 用法 | 怎么用 |
|---|---|
| **① 给选题池当判定依据**（主要用途） | 每日统一选题里，「小红书」那一行的 `✅ 有搜索词 / 🔄 换写法可搜 / ❌ 无搜索词` 不再靠人拍脑袋——**查这张表**。表里有 → `✅`；表里有近义词 → `🔄`（并直接写出该用哪个词）；表里完全没有 → `❌`。 |
| **② 反向倒推选题** | 从表里挑「有人搜、我还没写过、且跟我赛道对得上」的词，直接倒推成一条选题。这是公众号给不了的来源——**公众号选题来自"我想说什么"，小红书选题来自"用户在搜什么"，方向相反。** |

**它不做的**：不监控搜索量（小红书不公开）、不追热点榜、不做全站词库。**只做你赛道内、双周更新一次的一张表。**

---

## 技术路线（别改，这是试出来的）

**不要**逆向 `x-s` 签名——脆、易封、官方随时改算法。
**不要**解析下拉框 DOM——选择器一改就废。

**正确做法**：
用 CDP 接管一个**真实 Chrome** → 在搜索框里**逐字打字**（模拟真人）→ 页面自己的前端代码会带着完整的 cookie + `x-s` 签名去调 `/api/sns/web/v1/search/recommend` → 我们**从 CDP 的 Network 事件里读这条响应**。

好处：签名、登录态、反爬指纹全由页面自己处理，我们只读结构化 JSON。

> **实测结论（2026-10-10）：未登录状态也能拿到下拉词。** 不需要扫码登录，直接可用。
> 返回字段：`data.sug_items[].text`，一次 10 条。

## 前置：起浏览器

```bash
bash ~/.workbuddy/skills/小红书搜索词工作台/scripts/start-chrome.sh
```

- 端口 **9335**，独立 profile `~/xhs-keywords/.chrome-profile`
  （已知占用：9333＝公众号抓取，9334＝TikTok 店铺/广告，不要撞）
- 首次启动要**用 `run_in_background: true` + `dangerouslyDisableSandbox: true`**，否则进程被清理
- **不要用 `open -a "Google Chrome"`**——会把用户日常窗口调到前台
- **不要 `pkill -f "Google Chrome"`**（用户铁律：会杀掉他正在用的浏览器）。要停就按 profile 路径定位精确 PID

## 采集

```bash
cd "$HOME/xhs-keywords"
P=python3  # 需已安装 Pillow
$P ~/.workbuddy/skills/小红书搜索词工作台/scripts/collect.py --seeds seeds.txt --out output
```

参数：
- `--expand N`：对每个种子词的前 N 个联想词再做一次二级扩展（词表更厚，耗时翻倍；首次不建议开）
- `--wait 2.6`：每个词等接口返回的秒数。**取不到词就加大到 3.5**
- `--gap 1.1`：种子词之间的间隔。**不要调到 0.5 以下**，容易被限流

**时长参考**：30 个种子词约 **2 分钟**。超过 2 分钟的命令要用后台跑。

## 输出（都在 `xhs-keywords/output/`）

| 文件 | 用途 |
|---|---|
| `raw-YYYY-MM-DD.json` | 原始数据 |
| `keywords-YYYY-MM-DD.csv` | 三列：种子词 / 序号 / 联想词（可导入表格） |
| `词表-YYYY-MM-DD.md` | 按种子词分组的 Markdown → **归档飞书用这个** |

## 种子词怎么维护

文件：`xhs-keywords/seeds.txt`（`#` 开头是注释，一行一个词）

- 保持 **25~40 个**。太多没必要——下拉词互相重叠，边际收益递减。
- 分四组：①AI+素材生产（主业，最多）②AI+岗位提效 ③跨境 ④AI+个人/商业。
- 用户新增了业务方向 / 发现某类词抓不到东西 → 加减种子词，不用改代码。

## 归档到飞书（可选，用户要就做）

- 飞书文档正文用 `词表-YYYY-MM-DD.md` 的内容，`docs +update --command overwrite --doc-format markdown` 写入。
- **不要混进「内容作品库」**（那是作品归档）；词表属工具性资料，建议放「每日情报」或独立节点。
- 写入前先 `docs +fetch` 备份。

## 更新频率

**双周一次**即可（下拉词变化很慢，日更没有增量）。

## 已知坑（都是 2026-10-10 实测踩出来的，别重犯）

1. **输入框必须挑「可见且尺寸正常」的那个，不能写死 `#search-input`。**
   `#search-input` 是个 **0×0 的隐藏元素**（`getBoundingClientRect()` 全是 0），往里打字毫无反应。
   真正可见的是 **`#search-input-in-feeds`**（placeholder「我在小红书搞装修」，约 793×41）。
   脚本里的选法是：先筛 `w>120 && h>12 && 可见`，再优先 `#search-input-in-feeds`。**症状**：全 0 个词。
2. **下拉接口是「每敲一个字发一次」**：`keyword=A` → `AI` → `AI+主` → `AI+主图`。
   所以必须**按 keyword 精确匹配取整词那一条**（注意 URL 里空格编码成 `+` 不是 `%20`），取"任意一条"会拿到半截词的结果。**症状**：联想词看着像错的。
3. **页面被登录浮层接管后，输入框会变成 0×0。** 所以每次运行**先 `Page.navigate` 重载**回干净状态（脚本默认做，`--no-reload` 可关）。**症状**：第一次能跑，隔一阵再跑全 0。
4. **窗口不在前台时 `Input.insertText` 会被静默丢弃** → 每个词前调 `Page.bringToFront`。
5. **React 受控输入框直接赋 `el.value` 不触发请求** → 必须用原生 setter + 派发 `input` 事件（脚本已处理，input/textarea 两种原型都要顾）。
6. **页面是「未登录」状态完全没问题**，别去折腾登录，反而增加风险。
7. 彻底取不到词时，先 `curl -s http://127.0.0.1:9335/json/list` 看标签页还在不在；被关了重跑 `start-chrome.sh`。
8. 单个词取不到 → 脚本已自动重试一次；仍失败就把 `--wait` 从 2.8 调到 3.5。

## 词表怎么用（两条，别只当资料存着）

1. **回填选题池**：出每日选题时，小红书那一行的 `✅/🔄/❌` **查这张表**——
   表里有原词 → `✅ 有搜索词`；表里有近义/变体 → `🔄 换写法可搜`（**直接写出该用哪个词**）；表里完全没有 → `❌ 无搜索词`。
2. **反向倒推选题**：从表里挑「有人搜 + 我还没写过 + 跟我赛道对得上」的词。
   实测样例（2026-10-10）：
   - `ai电商主图哪个软件好用` → 选题「AI 做主图，到底哪个工具能用」
   - `ai抠图怎么快速把图抠出来` → 选题「AI 抠图 3 种抠法，哪种最快」
   - `跨境电商创业真实现状` → 选题「跨境创业的真相，跟你想的不一样」
   - `跨境电商培训` → 选题「花两万报的跨境课，值不值」
   **这类"带疑问词"的长尾词，命中率最高**——它直接就是用户的问题，也就是选题的钩子。
