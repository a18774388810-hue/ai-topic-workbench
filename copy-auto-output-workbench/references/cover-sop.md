## 风格规范（从业者审美：不 low、不商务）

- 底色：深灰蓝 `RGB(12,18,34)` + 细点阵装饰（间距 92 的 2px 圆点）
- 强调色：青 `(110,224,255)` + 品牌橙 `(255,159,46)`；正文白 `(245,248,255)`；辅助灰 `(150,165,190)`
- 字体：`SourceHanSansCN-Heavy.otf`，描边宽 = 字号/9 + 高斯投影；多色 segments 混排
- 单元素、低噪声、大留白；**封面标题要大**（用户反馈：偏小显弱，参考 16:9 封面两行 168/148px，范围 150-250px），卡片正文 80-130px。
- **公众号封面禁止解释性小字**：上传后会以标题缩略图展示，小字基本不可读。默认只保留 1 个主标题，优先两行同字号大字；副标题、说明、标签、落款一律不放，除非用户明确要求。标题整体放在画面上方约 1/3 区域，下半部分留空，方便上传后的封面裁切。
- 公众号封面如主标题已经足够有冲击力，可直接使用纯色/点阵底色 + 大字，不强制添加人物、场景图或装饰元素。
- **公众号封面字号同时受「宽度」和「2.35:1 裁切带高度」两个约束，且高度约束通常更紧**（2026-10-04 实测）：宽度往往只用掉 50% 左右，真正卡住字号的是裁切带。
  - 裁切带：`CROP_TOP = (H - int(W/2.35))/2`，`CROP_BOT = CROP_TOP + int(W/2.35)`；1920×1080 下即 **y ∈ [131.5, 948.5]**。
  - 标题组墨迹中心建议取 `Y_CENTER ≈ 0.36H`（390，约上方 1/3），fit 条件写 `height <= 2*(Y_CENTER - CROP_TOP) - 26`（26px 为安全余量）。
  - 反例：`Y_CENTER = H/3 = 360` 配 216px 字号时墨迹落在 y=60–660，**顶部被裁掉**。
  - 异号混排（如放大关键词）会显著抬高整组高度，**同字号版能做出的最大字号明显更大**（实测 176px vs 214px）；用户要求放大关键词时要在回复中说明这个代价。
- 小红书封面和文内卡片可继续使用左上角标签、左下角落款、发光播放键/时间轴/分镜帧等固定元素。
- **小红书封面「标题 + 真实界面截图」版式（2026-10-04 实践）**：用户提供产品界面截图、要求"放进封面并跟文字对应"时用。
  - 结构：顶部标签 → 标题（两行）→ N 张界面图竖排，**每张图下方紧跟一行对应说明**（图与文一一对应）→ 左下角款 + 右下页码。
  - 卡片处理：圆角 18 + 细边框 + 高斯投影 14，宽约 620px（1080 画布）。
  - 高度预算紧张时按此优先级压：先压图片宽度，再压说明字号，最后才动标题；标题低于 150px 会显得弱。
  - 三条实测坑：① `anchor="ls"` 的文字 y 是**基线**，说明行必须写成 `图底 + GAP + 字号`，否则文字向上压进图片；② 思源黑体**不含 emoji**（`👇` 变方块），序号别用 `①②③`（自带圆圈会与外画圆重叠），用纯数字；③ 检查脚本不要用 heredoc 写中文（会乱码），写成 `.py` 文件执行。
- **图内严禁出现站外引流字样（2026-10-04 用户明确要求）**：`GitHub`、公众号名、微信号、以及"品牌名 + 业务词"（如"尹晨俱乐部 · AI+电商"）一律不放进图里——小红书对这类内容会判定站外引流并限制分享，此前已实际触发过。**即使正文允许提，图里也不要出现。**

## ImageGen 背景 prompt 模板

关键三要素：**no text** + **留白方位**（上方/右侧）+ **克制**。
- 横版（公众号封面，1536x1024）：
  `Minimalist premium tech cover background, deep navy-slate solid backdrop, one glowing cyan play button center-left, thin timeline bar below, huge negative space upper/right for text, flat clean restrained, no text no letters no watermark, modern SaaS aesthetic`
- 竖版（小红书封面，1024x1536）：
  `Minimalist premium tech vertical background, deep navy-slate, glowing play button in rounded frame center, storyboard frames below, large negative space top for title, no text no watermark`
- 生成后必须 `kill_watermark`（右下 340×100 高斯模糊 16）。
- credit：约 5-10/张，生成前告知用户；每篇只生成 2 张背景，其余脚本绘制。

### 长标题封面：改用脚本自绘母题（2026-09-30 实践）
**触发条件**：主标题单行 ≥10 个汉字（如"实名举报！我被AI视频平台'小云雀'连续欺诈3次"这类新闻/维权题）。
**问题**：AI 生成背景的视觉主体位置不受控，文字一铺开就压上去；如果靠裁切去避让，主体常被切得只剩残缺色块，母题直接失效（实测：三环母题被右边缘切成两个"透镜"）。此时**不要**反复重生成背景去碰运气。
**做法**：
1. 背景直接用 `new_canvas()` 的纯色 + 点阵底（本 SOP 已允许："主标题足够有冲击力时，可用纯色/点阵底 + 大字"）。
2. 母题（三环、方块、播放键等）用 PIL 自绘：先铺一层 `GaussianBlur(20)` 的发光层，再压清晰描边，最后加细引线。完全可控、0 credit。
3. 参考实现：`<你的项目目录>/make_gzh_cover.py` 的 `rings()` 函数。
4. 标题字号按 `max_w = 可让出的右侧宽度` 反推；两行同字号时用 `seg_w()` 先量宽度再定字号（142px 实测足够有冲击力，不必强求 150+）。
**裁切自检（必做）**：微信列表按 2.35:1 **居中**裁切，即只剩 y∈[(H-817)/2, (H+817)/2]。生成后用脚本额外存一张 `_预检-列表缩略图2.35x1.jpg` 目视确认——标题和母题**都要**落在这个带内，否则列表页里会被切掉。（首版三环放在 y 942~1058，列表页会被砍掉一大半。）
- **跨工具（Codex 等）**：`ImageGen` 是 WorkBuddy 内置，其他环境换成任意图像生成工具（OpenAI API / DALL-E / 图像 MCP），照上面 prompt 出背景图再交给 make_*.py 叠字即可（详见 `CODE_X.md`）。

### 两行标题做「左右两端对齐」（2026-09-30 实践）
用户会要求封面标题两行**左右都齐边**（上下等宽）。中文两行字数不等时有两种解法：
- **A 逐行字号**：各给不同字号使 ink 等宽。缺点：字号差通常 15%+，上大下小容易被当成排版失误。实测 L1=165px / L2=143px，差 22px。
- **B 等字号 + 短行疏排**（**推荐**，符合本 SOP「优先两行同字号大字」）：统一字号，给字少的那行加字距撑到同宽。实测 L1 11 字 / L2 12 字，同用 143px，首行加字距 15.9px（11.1%）即两端齐平。字距一旦 >15% 会显散，此时应优先调整断句把两行 em 数拉近，而不是继续加字距。
**两个必踩的坑**：
1. **别用 `font.getlength()` 的 advance 宽度算等宽**——advance 含字面侧边距，实测右边缘会差约 40px。正确做法：在独立 `Image.new("L", …)` 画布上逐字绘制，取 `getbbox()` 量 **ink 宽度**，再线性反解字距（ink 宽度对字距是线性的）。左边缘对齐同理，按首字 ink 左偏移修正 x。
2. **逐字绘制 + 描边会互相吃边**（后一个字的深色描边盖掉前一个字的填充）。解法：**先把整行所有字用深色粗描边铺满一层 `alpha_composite`，再把彩色填充整行压上去**；投影层单独 offset(+5,+8) + `GaussianBlur(7)`。

**自绘多行标题：画布高度与基线必须用 `getmetrics()`（2026-10-08 实测）**
`anchor="ls"` 的 y 是**基线**，不是字顶。若把画布高度写成 `size*1.6`、基线写成 `pad + stroke_w`，字形中上部会落到画布外被裁掉——渲染出来像一堆缺了上半截的乱码方块，**极易误判成"字体损坏/缺字"**（实测思源黑体本身完好，白折腾一轮）。
- 正确写法：`asc, desc = font.getmetrics()`；画布高 = `asc + desc + stroke_w*2 + pad*2`；基线 y = `pad + stroke_w + asc`。
- 自检：拿一个已知字串单独渲染成白底黑字小图看一眼，能读通再跑正式封面。
**收尾自检**：成品出来后用 numpy 按行带 `(band > 90).any(axis=0)` 统计高亮像素列范围，确认两行 x 边界一致（实测 127~1700 / 128~1699，两侧各差 1px 即达标）。
