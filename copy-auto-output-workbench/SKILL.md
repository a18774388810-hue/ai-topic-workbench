# 文案自动化输出工作台

五步闭环：**热点选题 → 选稿 → 风格化创作 → 配图 → 交付**。

## -1. 拿到公众号定稿时：先判定，再转化（2026-10-10 用户要求，强制）

**不要再拿到公众号稿就默认"缩写 → 小红书 + 口播"。** 有些文章的**选题本身**就不适合推荐流平台，缩写只是把不适合的内容换个长度再发一遍。

所以每收到一篇公众号定稿，**第一步先出「平台适配判定」**，逐平台分析抖音/视频号/小红书的推流逻辑与用户兴趣，给三种结论之一：

- **① 明确不适合**（并说明如果要发必须先改什么）
- **② 适合，可直接缩写**
- **③ 适合，但要换角度/换主题**（给 2-3 个可独立成篇的新选题，用户选一个再写）

**判据、三关尺子、三个平台的差异、固定输出格式、以及已踩过的案例，全部见 `references/platform-fit-check.md`（每次必读）。**
一句话原则：**推荐流的生死线是"内容能不能被打上标签"；打不上标签，内容再好也出不去。**

> **例外：播客不受本判定限制。** 播客是订阅/长音频，听众也是冲着"尹晨这个人"来的，所以**任何公众号文章都可以转播客**，不需要过三关尺子。转播客见 `references/podcast-script.md`。

## -0.5. 公众号 → 播客文案（2026-10-10 用户要求，常备动作）

用户会把公众号文章**口播录成音频发到播客**，但直接念公众号原文"读起来怪怪的"。所以每篇公众号定稿，**默认同时产出一份播客文案**：

- **不删减** —— 播客时长本来就长，全文内容都留，只做口语化改写（不许提炼、不许缩写）。
- **固定骨架**：第一句是**标题** → 第二句是**导语（每次由我生成一句话）** → 第三句是固定开场白「哈喽，欢迎收听我的 AI+电商频道，我是尹晨，每一期给大家分享 AI+电商实操观点。」
- **固定结尾**：「好了今日播客分享完毕，最后送给大家一份非常详细的 AI 加电商干货资料，主页有我的联系方式，欢迎来领取！」
- **开场白与结尾文案一字不改**。
- **播客不受上面「平台适配判定」限制**（订阅制，听众冲"这个人"来），任何公众号文章都能转。

> **完整规则已独立成技能：加载 `公众号转播客文案工作台`（`~/.workbuddy/skills/公众号转播客文案工作台/SKILL.md`），按它执行；本文件不再重复维护规则。**

## 0. 内容定位（选题筛选的硬标准）

- **主赛道 AI×电商**：平台侧重抖音电商 + 跨境电商（次小红书/视频号）
  - ① **AI 素材创作**（主图/带货短视频/详情页/直播贴片）
  - ② **AI 岗位提效**（运营/客服/投流/美工/文案）
  - ③ **AI+电商行业趋势**（以电商行业为主体、AI 为变量：AI 正在怎样改变电商行业——素材生产力 / 岗位结构 / 竞争格局 / 平台生态 / 行业风向，讲变化趋势，**不硬套 AI 产品/技术新闻**）
- **副赛道 AI×商业/企业**：AI 内训、企业落地部署（FDE）
- 筛选题万能句：「这条 AI 动态，能不能立刻变成抖音/跨境卖家手里的**素材生产力**或**岗位提效工具**？」

## 1. 每日上午：出统一选题（四栏 × 4 = 16 个）

> **唯一出题口径**：本工作台与「短视频工作台」**共用同一份选题池**。不再分别出「文案选题」和「短视频选题」——每天只出一份。
>
> **2026-10-10 口径修正（重要）**：旧规则要求"每个选题都必须同时撑得起公众号 3000 字深度文和短视频 60~90 秒口播，写不出钩子就淘汰"。**这条已废弃**——用户主战场是公众号，硬把"能不能拍短视频"当准入门槛，会把本来该写给公众号的好选题提前毙掉；而真实的坑在反面：**写完 3000 字才发现转不了推荐流，等于白等一天**。
>
> 新口径：**立项时就把每个渠道的落点写清楚**，**判定从"事后"提到"立项"**。

1. 用 WebSearch 抓 24-48h 内 AI 行业动态（大模型发布、AI 工具上新、平台政策、行业事件），关键词组并行搜。
2. 每个选题必须给三点：
   - **① 是什么**：一句事实，**必须标注准确的发布时间/时效状态**（如「9/26 新发布」「9 月 22 日」「早前发布·近期热议」），防止用户误判新旧导致内容爆雷（教训：Wan3.0 是 8 月上线，曾被误写成"今天云栖发布"）。
   - **② 为什么选**：时效性 + 受众痛点 + 爆款角度。
   - **③ 渠道落点**：逐渠道标出能不能吃、怎么吃——
     - **公众号**：写主稿角度，一律 ✅（主战场，不判断）
     - **抖音 / 视频号**：写 3 秒钩子，标 `✅ 可转` / `🔄 换角度`（写明换成什么角度）/ `❌ 不可转`（一句话说清为什么）
     - **小红书**：写**搜索词**，标 `✅ 有搜索词` / `🔄 换写法可搜`（写出换成哪个词）/ `❌ 无搜索词`
     - **播客**：默认全可转，**不占字段**
     - 末尾给**结论**：`🌟 三端通吃` / `📱 推荐流强` / `📖 仅公众号`
3. 固定四栏、每栏 4 个，栏内按「时效 + 痛点 + 爆款潜力」排序，每栏末尾标 1 个重点推荐（优先推 `🌟 三端通吃`）。
4. **每栏至少 2 个 `🌟 三端通吃`**，不允许整栏 4 个全是 `📖 仅公众号`。
5. 用户按「栏目 + 编号」选定 1 个。选定后**按该题的「渠道落点」执行**：`✅` 的渠道直接产出，`🔄` 的按写明的换角度方案产出，`❌` 的渠道不发。

> **完整口径（含固定排版格式与「仅公众号」示例）见 `references/topic-guide.md`——出题前必读。**

> **③ 栏口径（关键，勿偏）**：以电商行业为主体、AI 为变量，讲「AI 正在怎样改变电商行业」——素材生产力、岗位结构、竞争格局、平台生态、行业风向；**不要**拿某个 AI 产品/技术更新硬套电商。①②④ 才允许直接以 AI 产品/工具为出发点。
> **四类内容混合**：①爆款案例（必须真实可信，优先官方数据/上市公司财报/平台政策/公认行业现象，绝不用营销软文、论坛传闻的"单品爆款数字"）②行业事件 ③工具/模型更新（讲对做电商的实际影响）④博主行业视角/观点。
> 四栏完整口径与选题方向清单见 `references/topic-guide.md`（出题前必读）。

## 2. 风格画像（强制铁律，无需用户提示）

**铁律：紧扣尹晨飞书文档的写作风格，是默认强制行为，不因用户是否提示而改变。**（用户明确反馈：提示前后差别巨大，所以永远默认开启，无需再等提示。）

**风格画像文件未随仓库开源**（那是作者个人的写作风格画像）。导入后请自备一份 `references/style-profile.md`。两层都要到位：
- **表层风格**：标题钩子 / 第一人称"我"+真实经历+具体数字 / 口语词+反问 / 观点先行→列举→金句收尾 / 辩证务实。
- **深层风格（"像不像"的关键）**：必须援引他飞书里沉淀的具体方法论、判断框架、原话、个人经历（如「3 优势=10 弱势」「数出 3 个优点逼自己数出更多缺点」「当下能不能解决/未来三个月靠钱资源能不能解决」「素材质量大于一切」）。光套语气不像，援引他的"思维框架"才像。
- **援引飞书内容 = 充分非必要**：恰当时候引用他的原话/经历能带来"活人感"，是加分项，但不强求每篇都引。
- **行业知识 + 金句弹药库**：原实现见 `references/industry-knowledge.md`（提炼自作者两本原创教程）——**该文件未随仓库开源**。请自备一份自己行业的同结构文件。

## 3. 文案规格（字数档位，用户已拍板）

| 平台 | 类型 | 字数 |
|---|---|---|
| 公众号 | 一律深度文 | **3000 字左右（默认 2800–3200）** |
| 小红书 | 观点/干货笔记 | 300–500（默认 ~400） |
| 小红书 | 清单/合集笔记 | 400–600 |

- 公众号**不再写快评短稿**，统一按 3000 字深度文写（用户明确："3000 字左右最合适"，2868 字那篇被认定"非常精彩"）。
- 双平台一起交付；公众号短段落高频换行；小红书带符号排版 + 话题标签。
- **完整文案必须直接写在消息正文里**（用户习惯：不翻聊天记录/文件找文案）。

## 4. 配图 SOP

详见 `references/cover-sop.md`。要点：
- 公众号：封面 **16:9（1920×1080**，上传后列表自动裁 2.35:1 展示，一张即可、无需 1:1 备用；AI 生成科技背景 + 脚本叠字）；文内图 3 张 16:9（对比/金句/方法，脚本绘制）。
- 小红书：6 张 **9:16（1080×1920）**，内容卡带页码角标 2/6~6/6；固定阅读路径 = 封面 → 观点 → 痛点 → 对比 → 方法 → 金句。
- 风格：深灰蓝 + 青 + 品牌橙，单元素克制，「不 low、不商务」。
- 只用 ImageGen 生成 2 张封面主视觉背景（prompt 必须含 no text + 留白方位），其余文字卡片用脚本绘制省 credit。
- ImageGen 消耗 credit（约 5-10/张），生成前告知用户。

- 用户的修改意见（风格、字数、配图偏好、平台规则变化）及时回写本 skill 与 references。
