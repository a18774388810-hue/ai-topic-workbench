# 短视频工作台（尹晨日更生产线）

> ## 🚩 第一红线（2026-09-28 用户反复强调，违反即为废片）
> **字幕与画面文字，必须以他录音里实际说出的内容为唯一基准。**
> 他录音时一定会临场改稿。**绝不允许**把先前给出的口播稿措辞回填到字幕/卡片上——那会造成"他嘴里说的"与"画面里写的"不一致。
> 正确流程：转写 → 只纠同音错字（专有名词必错：如"蔡克勇/陈丹琪"应为"蔡康永/陈丹青"）→ 直接作为字幕与卡片依据。
> 交付"口播文案"时同理：**输出的是他实际说的那一版**，不是原先的稿子。
> 音频里若有重复重录段，先确认用户是否已自行剪掉；不要擅自剪音频，确需剪必须事前说明并说明改动位置。

把一条选题变成可发布竖屏成片：**选题 → 口播文案 → 录音 → 合成 → 封面**，全流程本地完成，无需剪映/Hypit。这是尹晨每天发一条短视频的统一入口。

## 完整链路（5 阶段）

| 阶段 | 谁做 | 产出 | 说明 |
|---|---|---|---|
| ① 选题 | 工作台/自动化 | 统一选题池 16 个 | 每天 12:00 automation「每日统一选题（文案+短视频）」出题；**与文案工作台共用同一份池子，不再单独出短视频选题** |
| ② 口播文案 | 工作台 | 文案 + 分句配图表 | 60~90 秒 / 250~400 字 |
| ③ 录音 | **用户** | mp3/视频 | DJI Pocket 或手机，唯一必须用户动手的环节 |
| ④ 合成 | 工作台 | 成片 mp4 | 本 skill 的核心管线（见下） |
| ⑤ 封面 | 工作台 | 3:4 + 4:3 两张 | 引用 `短视频封面工作台`（抖音/视频号专用尺寸+安全边距）；如需 16:9/9:16 等通用尺寸用 `cover-four-size-generator` |

## ① 选题（与文案共用同一份选题池）

**不再单独出选题。** 每日 12:00 的「每日统一选题（文案+短视频）」automation 与本工作台、`copy-auto-output-workbench` **共用同一份四栏选题池**：

- **① AI+电商素材生产**
- **② AI+岗位提效与降本**
- **③ AI+电商趋势与观点**
- **④ AI+商业与企业落地**

每栏 4 个、共 16 个。出题口径、时效标注要求、**渠道落点**要求、四类内容混合规则，全部见 `copy-auto-output-workbench` 的 §1 与 `references/topic-guide.md`（唯一口径来源，勿在此另立标准）。

**（2026-10-10 修正）同题不再默认三端全发。** 每个选题在出题时已带「渠道落点」，标了 `✅ 可转` / `🔄 换角度`（写明换成什么）/ `❌ 不可转`。**本工作台只接抖音/视频号标了 `✅ 可转` 或 `🔄 换角度` 的题**；标 `❌ 不可转` 的通常也在标 `📖 仅公众号`，不要硬拍。

**进入写口播的前提**：该选题的抖音/视频号落点不是 `❌`。是 `✅ 可转` → 直接用池子里的 3 秒钩子进 ②；是 `🔄 换角度` → 按写明的换角度方案写钩子，再进 ②。

## ② 口播文案规格

- **60~90 秒 / 250~400 字**，纯口语、短句、留气口，方便照着念。
- 结构 = 3 秒钩子 → 正文 2~3 个要点 → 收尾（观点/CTA）。
- **必须附带「分句 + 配图方向」对照表**（每句话切分，标注卡标题 + 画面类型），供录音后直接配图合成，不再重复分析。
- 全文直接写在消息正文，用户拿到即录。

## ③ 录音

用户录好 mp3/视频发回，进入合成阶段。

## ④ 合成管线（原 talking-card-video 核心，scripts/ 内为可复用模板）

把口播变成竖屏成片：主画面 = 按句切换的演示卡 + 底部圆形真人小窗 + 逐句字幕。

### 输入
1. 口播（视频或音频，视频需提音轨）
2. 真人小窗素材（竖屏视频，台上分享/坐着讲话均可，30s 左右可循环）
3. 主画面风格（**默认暗黑科技风**，改 make_cards.py 配色常量）：
   - **A 白底科技演示**：白底 + 深灰蓝 #111834 + 品牌橙 #FF9F2E
   - **B 暗黑科技风**（配《星际穿越》等史诗氛围乐，当前默认）：深空渐变背景 #030408→#070910（中性黑，勿偏蓝）+ 星点；主文字 #EAF2FF、强调橙 #FF9F2E、科技青 #6EE0FF、深蓝块 #162442/#1E345C；插画用 dark space + neon cyan/orange glow 重生成；字幕白字+黑描边；切出黑 blend
   - **竖屏布局铁律**：标题 y170-292 / 视觉区 ≤1240 / **字幕 y1260-1360（小窗上方，避开抖音/视频号底部文案遮挡）** / 小窗 y1400-1700 / **落款 y1730（小窗正下方居中）**

### 合成 7 步
1. **提音轨**：`ffmpeg -i 口播.mp4 -vn -ac 1 -ar 16000 koubo.wav`（音频直接转）
2. **转写**：`transcribe.py` — faster-whisper small **必须传本地 snapshot 路径** + `env -u HTTP_PROXY ...`（详见脚本）。whisper 分段即天然逐句时间戳。**字幕必须紧扣口播实际内容**：用户录音常临场改稿，字幕以 whisper 转写原文为唯一基准、只纠明显同音错字，绝不回填文案稿措辞。
3. **校对整理**：纠同音词（专有名词必错），整理成分句+时间戳稿 `segments.json`（start/end/text/visual 配图方向），给用户过目。
4. **配图（图层化）**（`make_cards.py`）：每卡输出 `cards/cardN/bg.png`（底图+pill+落款，静止）+ `L1..Ln.png`（透明元素层）+ `cards/anim.json`。**每层带持续动效 motion**：float（上下漂浮）/ breathe（呼吸缩放，给视觉主体）/ pulse（脉冲缩放，给强调元素），配合 delay 错峰入场。绝不让整卡一起动。需要意象画面的句子（2-3 张）→ ImageGen，prompt 必须 no text + flat tech illustration + 蓝橙点缀；中文文字一律 PIL 叠。**涉及具体产品/工具时，抓官网真实界面做 `browser_card()` 特效**（浏览器窗口+三圆点+地址栏+辉光边框+来源角标），比抽象插画更有说服力。
5. **字幕层**（`gen_subs_overlay.py`）：解析 subs.ass → 每句一张 1080x1920 透明 PNG（白字+黑描边，暗底；小窗上方居中，多行手动 \N）
6. **小窗**：`ffmpeg -i 素材.mp4 -vf "crop=720:720:0:100,scale=300:300" winf/%04d.jpg` 抽帧；**先抽帧检查**，剔除原视频自带贴纸/字幕/箭头的时段，用干净区间循环
7. **合成**（`render_frames.py`）：PIL 逐帧（bg 静止 → 每层按 anim.json 入场(up 上浮 90px / scale 1.22 弹出 ease_out_back / slide ±100 滑入，delay 错峰) → 稳定期按 motion 持续动效（float/breathe/pulse 相位错开）→ 漂浮装饰层 → 圆形小窗 → 字幕 → 卡末 0.2s 微淡出）→ rgb24 pipe → ffmpeg 编码
8. **音频**（`mix_bgm.py`）：真实 BGM 文件（用户提供 mp3）→ ffmpeg 转 48k mono → numpy 循环铺满时长 + 淡入淡出 + 音量系数(0.20) + 口播混音 → mixed.wav。占位 BGM 用 gen_audio.py（和弦 pad）兜底。
9. **封面（必做，勿漏）**：出片后**立即**做多尺寸封面（见 ⑤），**交付成片时封面必须一起交付，漏封面 = 任务未完成**。抽帧要 `-vf "crop=1080:1240:0:0"` 裁掉底部字幕区(1260-1360)和小窗区(1400-1700)，只留主画面，否则封面背景会带字幕小窗。

## ④b 意象画面插入（纯文字卡「缺乏丰富性」时的标准升级）

> 触发：用户说「画面缺乏丰富性」「插入一些画面」「上一个视频那样有画面」。纯卡片片子在 30 秒后会显得平，插入意象画面是最有效的升级手段。

**选点原则**：只挑**承重的语义段落**，约 6~8 处，覆盖全片 30~40% 时长；不要整片都换画面（会失去卡片的信息功能）。优先选：有具体场景的叙述句、名人引述、核心概念（如「合流」）、情绪转折处、结尾。

**素材生成（ImageGen）**
- 竖构图 `size=1024x1536`，统一风格后缀：`cinematic film still, vertical composition, deep shadows, moody dark atmosphere, muted desaturated palette, 35mm film grain, large negative space at the top, no text, no watermark`。
- 顶部必须留暗部空区（给文字），主体安排在中下部。
- **人物一律用背影/剪影，明确写 `no face visible`**；名人肖像不用真人照片，改用**呼应其内容意象 + 名字引述卡**（如「面包的香味」「钟摆」），规避肖像权且更契合"深邃"。
- 生活/散文类主题用**电影感实拍风**；AI/科技类主题才用 flat tech illustration。

**素材处理铁律**
- **ImageGen 生成的图右下角会带「Ai生成」水印**：cover 前先裁掉底部 7%（`im.crop((0,0,w,int(h*0.93)))`），再按 `max(W/w, H/h)` 缩放 + 居中裁切，水印即完全消失。
- **逐张单独调明暗**：同一批图曝光差异极大，必须为每张单独设 `brightness/color`（暗图提到 1.4~1.5 倍，亮图降到 0.8），否则会出现"有的全黑有的发白"。统一 `Contrast 1.06`。
- **生成后立刻按语义重命名**（`scene1_office.png` 等），不要依赖时间戳文件名。

**Ken Burns 缓动（静帧造出动感）**
- 预处理：把 cover 后的图预先放大到 `1.12 × (1080×1920)`，逐帧从大图 crop 一个 `(BW/s, BH/s)` 窗口再 resize 回 1080×1920；`s` 从 `zoom[0]` 线性变到 `zoom[1]`。
- 每段给**不同方向**（推近 / 拉远 / 左移 / 上移），避免机械感。用 `pan` 控制 crop 中心漂移。
- 每帧 crop+resize 用 `Image.BILINEAR`（LANCZOS 在此倍率下收益不大、耗时翻倍）。

**画面卡布局（关键，勿与既有安全区打架）**
- 文字区固定在**上部 y≈560**（画面主体在中下部、字幕在 y1308，三者互不重叠）。
- 文字层做成一张预生成的 RGBA overlay（`make_overlay`），每帧只需 `alpha_composite`，不要逐帧重绘。
- 顶部渐变衬文字：`alpha = 172 × dim × (1-k)^1.7`，覆盖 y0–1000；**亮背景的图（天空、雪、白墙）把 `dim` 调到 1.4~1.6**。
- 底部渐变只为字幕服务，要轻：**420px、alpha 上限 140**，起点 y1500。做太强会把画面主体（奔马下半身等）压黑。
- **overlay 必须用 RGBA 安全的绘制函数**：原 `draw_centered` 内部 `convert("RGB")` 会丢掉 alpha，需改写为 `alpha_composite` 版本。

**交付前**：跑 `render_video.py probe`，对每段画面抽 start+0.4s / 中点 / end−0.4s 三帧拼图目检，确认画面主体可见、文字不压主体、字幕不与画面打架。

**实测代价**：8 张图 ≈ 40~80 credit，渲染多约 1 分钟。相比替换成 AI 视频（300~600 credit）性价比极高。

## ⑤ 封面（引用 cover-four-size-generator）——**必做，和成片一起交付**

- **红线：出片必配封面。只给视频不给封面 = 任务未完成**（2026-09-24 用户明确要求，别再漏）。
- 每个尺寸用当天这条视频的**抽帧做背景**（每条视频有自己的元素，不千篇一律黑底）。
- **抽帧先裁主画面**：`ffmpeg -ss <代表帧秒数> -i 成片.mp4 -frames:v 1 -vf "crop=1080:1240:0:0" frame.png`，去掉字幕/小窗后再做背景；若底部还有卡片内橙字和封面标题冲突，继续收窄 crop 高度。
- **硬规则**：抽帧背景若杂乱/自带明显文字，叠标题前**必须加压暗 + 半透明黑罩图层**，否则标题喧宾夺主。
- 尺寸：4:3(1920×1440) / 3:4(1440×1920，抖音安全比例) / 9:16(1080×1920)。
- 脚本：`cover-four-size-generator/scripts/frame_bg_cover.py`，标题拆两行（`--line1` 白字 + `--line2` 关键词用 `|` 分段橙色强调）。

## 硬坑（必须遵守）

- **官网抓界面用 curl 提取图片资源，别用 Chrome headless 截图**：本机 Chrome headless 反复 SIGKILL(137)。正确路径：`curl -x http://127.0.0.1:7897 官网URL` → grep 出 `(src|href)="...png/webp/svg"` → 下载官方插图（常带透明 RGBA，可直接贴暗底）。
- **抓「产品界面」要看 GitHub README 的 user-attachments 截图，别用官网首页营销插图**：官网首页图多是粉色抽象营销插画，不是界面、和暗黑风不搭。真实界面在 README 的 `![...](https://github.com/user-attachments/assets/...)` 链接里。下载前用 PIL 分析像素判断是不是"界面"。
- **本机 /opt/homebrew/bin/ffmpeg 9.0.1 是裁剪构建**：无 subtitles、无 drawtext、无 filter_complex_script（只支持单流 -vf）。多输入合成只能走 Python 逐帧渲染 + rawvideo pipe，不要尝试 filter_complex。
- **ImageGen 并行调用会同名覆盖**（时间戳只到秒），且 **`output_dir` 参数可能被忽略、图片全落到上一次的目录**：一律**串行单张生成**，每次生成后立刻 `find` 核对文件数量并按语义重命名，缺了补生成。已实测：4 张并行会丢 1 张。
- **逐帧渲染底图必须每帧 copy**（白环预画进卡底图），否则字幕层跨帧累积出残影。
- **crop 越界 = PIL 静默填黑**：漂浮 crop 的 y 坐标必须用 `b.size[1]`（高）算，误用宽度变量会让画面顶部出黑块（实际踩过）。任何 crop 前核对 box 全部 ≥0 且 ≤尺寸。
- ffmpeg 图片序列输出单文件必须 `-update 1 -frames:v 1`。
- 小窗素材先抽帧人工检查：开场贴纸字幕、红色箭头等都是雷；小窗静音使用（音轨只有口播）。
- 字幕时间段从 whisper 分段直接取，比手工对轴准；长句手动 \N 分行（一行 ≤16 字）。
- **卡片切换必须服从口播语义时间轴**：禁止按固定间隔机械切卡。卡片只能在一句完整语义开始前切入，不能在口播半句中途换画面；必须直接使用校对后的 whisper 起始时间作为 `card_timing`。
- **字幕拥有最高视觉优先级**：字幕固定在 y1260-1360 独立安全区；卡片说明字能删就删，尤其不得复述同期口播。保留的卡片标题仅放 y170-320，视觉/视频区底边不得超过 y1100，二者之间必须留白。
- **动态视频页面用减法**：有视频窗时只保留一个顶部主题标题，删除视频下方说明字和功能堆叠；视频窗固定上移，不得覆盖标题、字幕或真人小窗。
- **交付前碰撞核验**：至少按每个字幕事件中点和每个卡片切换点前后各抽一帧，检查卡片文字×字幕、卡片文字×视频、视频×字幕三类碰撞；发现任一碰撞必须重排后再交付。

## 复用方式

新主题：拷 `单人短视频demo/` 目录结构 → 只改合成阶段的 ②③④ 步内容（segments.json 的 text/visual、make_cards.py 里的卡片文案与绘制）→ ⑤⑥⑦ 原样跑。若口播稿是先写好的（如口播文案），可跳过转写校对，直接按稿录音后走 ①。

- 口播录音 / 转写 / 卡片(PIL) / 官网截图 / 小窗裁切 / 字幕 / 合成 / BGM = 0 credit。
- 唯一花钱处：可选 AI 插画（ImageGen 5~10 credit/张）。纯文字+图标+截图卡片 = 0 credit。
